# maxmix — подробности

Утилита для Windows (Go, только стандартная библиотека): собирает звук игры и
Discord в одно виртуальное устройство и переключает на него запись звука в
**Steam Game Recording** и **NVIDIA App (ShadowPlay)**. В записи слышно и игру,
и голосовой чат, независимо от того, в какие наушники или выходы они играют.

Живёт в трее: правый клик → «Настройки», «Открыть лог», «Выход». Двойной клик
по иконке открывает настройки.

## Как это работает

1. **Виртуальное устройство** — драйвер [VB-CABLE](https://vb-audio.com/Cable/)
   (бесплатный, подписанный): пара `CABLE Input` (воспроизведение) /
   `CABLE Output` (запись). Виртуальную звуковую карту в Windows создаёт только
   kernel-драйвер, поэтому maxmix ставит готовый (`maxmix install-cable`).
2. **Захват** — process loopback (Windows 10 2004+, тот же механизм, что у
   Steam): звук конкретного процесса, куда бы он ни играл. Источники:
   - **Игра (авто)** — детектор смотрит на процессы с аудиосессией и считает
     игрой тот, у которого окно на переднем плане или окно без рамки на весь
     монитор, либо который запущен из Steam/Epic/Battle.net/GOG/Ubisoft/EA/Riot.
     Браузеры, лаунчеры, сами рекордеры и т.п. исключаются списком. Найденная
     игра «прилипает» до её закрытия, alt-tab её не сбрасывает. Захватывается
     всё дерево процессов игры, лаунчер — нет.
   - **Программа** — конкретный exe целиком (`Discord.exe` со всеми дочерними).
   - **Всё, что звучит** — все процессы с аудиосессией минус исключения.
   - **Устройство** — WASAPI loopback всего, что играет на выбранном выходе.
3. **Микшер** складывает источники (с индивидуальной громкостью) и играет в
   `CABLE Input`. Наушники работают как раньше, ничего не переназначается.
4. **Steam и NVIDIA** не дают выбрать устройство системного звука; они пишут
   loopback с устройства «по умолчанию» своего процесса. maxmix задаёт для
   `steam.exe`, `nvcontainer.exe`, `NVIDIA Overlay.exe` персональное устройство
   `CABLE Input` (то же, что Параметры → Звук → Микшер громкости, тот же
   внутренний API, что у EarTrumpet).

Steam-у включите *Настройки → Запись игр → Записывать звук: «Весь системный
звук»*, иначе он пишет только процесс игры.

## Сборка

```bat
build.cmd
```

Скрипт рисует иконку (`tools/mkicon` → `assets/maxmix.ico`), упаковывает её в
`rsrc_windows_amd64.syso` (`tools/mksyso`, вместо стороннего rsrc) и собирает
два бинарника из одного кода: `maxmix.exe` (трей, `-H=windowsgui`, без
консольного окна) и `maxmixc.exe` (консольный, для команд из терминала: PowerShell
не ждёт завершения GUI-программ, поэтому вывод `maxmix.exe devices` может не
успеть показаться).

## Использование

```
maxmix                    # трей + микшер + переназначение Steam/NVIDIA (двойной клик по exe)
maxmix run -settings      # то же, сразу с окном настроек
maxmix run -no-route      # не трогать Steam/NVIDIA
maxmix install-cable      # поставить VB-CABLE (UAC), после установки часто нужен перезапуск
maxmix autostart          # запускать при входе в Windows (autostart -remove — убрать)
maxmix game               # что детектор сейчас считает игрой и почему
maxmix sessions           # кто сейчас издаёт звук (pid, exe, устройство)
maxmix devices            # список устройств
maxmix status             # какое устройство выставлено у steam/nvidia
maxmix route / unroute    # выставить / снять переназначение вручную
maxmix config             # действующая конфигурация
```

Лог: `%LOCALAPPDATA%\maxmix\maxmix.log` (есть в меню трея).

## Окно настроек

Оформление в духе WinUI 3 (как у Mica For Everyone): слева навигация с иконками
Segoe Fluent Icons, справа страница с карточками «иконка, название, описание,
контрол», тумблеры, выпадающие списки в виде кнопок с тёмным меню, списки с
собственной отрисовкой строк. Тёмная или светлая тема берётся из системной
настройки «Режим приложения» и переключается на лету. Всё нарисовано на Win32 и
GDI без сторонних библиотек ([theme.go](../theme.go), [draw.go](../draw.go),
[settings.go](../settings.go)).

- **Входы** — тумблер «Определять игру автоматически» (в описании видно, какая
  игра найдена), список источников с уровнями захвата, редактор выбранной строки:
  тип, значение (с подсказками из звучащих процессов или устройств), громкость,
  исключения для авто-режимов.
- **Звучит сейчас** — процесс, PID, устройство, статус, попадает ли в запись.
  Кнопки «Добавить как вход» и «Исключить из авто».
- **Выход и запись** — виртуальное устройство, уровень микса, список программ
  записи, состояние переназначения и кнопки «Направить на выход» / «Снять».
- **Проверка** — самопроверка записи, см. ниже.
- **Общие** — язык (русский / английский, по умолчанию как у Windows; в
  `maxmix.json` это поле `"lang"`), автозапуск, журнал, установка VB-CABLE,
  о программе, выход.

Установка VB-CABLE не меняет устройства по умолчанию: установщик делает кабель
устройством по умолчанию, maxmix запоминает прежние устройства (воспроизведение
и запись, все роли) и возвращает их, как только кабель появился. Посмотреть или
поправить вручную: `maxmixc default` и `maxmixc default <имя> [communications]`.
- **Сохранить и применить** — пишет `maxmix.json` и перестраивает микшер на лету.

## Самопроверка

Страница «Проверка» в окне или `maxmixc selftest [секунды]`. Во время проверки
включите звук в игре и скажите что-нибудь в микрофон. Проверка ничего не
переключает: каждый замер это отдельный независимый захват через WASAPI, а
микрофон только читается ([selftest.go](../selftest.go)).

Что проверяется:

- виртуальное устройство найдено;
- **в записи есть звук** — loopback того же устройства, с которого пишут Steam и
  NVIDIA, то есть ровно то, что попадёт в клип;
- **каждый вход по отдельности** — свой захват процесса или устройства, с пиком
  в dBFS; отдельная строка «Несколько источников» говорит, сколько входов реально
  дали звук, и перечисляет молчащие;
- **микрофон** — уровень, mute и громкость устройства записи по умолчанию.
  Системное устройство записи при этом не меняется. Если микрофон добавлен
  входом микса, проверка это показывает и предупреждает о двойной записи голоса,
  когда микрофон включён ещё и в самом рекордере;
- **прослушивание микрофона** — только на время проверки. Выберите устройство в
  строке «Прослушивать микрофон», и во время замера вы услышите себя в наушниках.
  Постоянного прослушивания нет;
- **настройки Steam** — фоновая запись, что именно он пишет, выбранные программы
  (их привязка устаревает после обновления приложения), микрофон и идёт ли
  запись на диск прямо сейчас ([steamcheck.go](../steamcheck.go));
- **настройки NVIDIA App** — включён ли в NVIDIA микрофон и какой именно
  (из реестра `HKCU\Software\NVIDIA Corporation\Global\ShadowPlay\NVSPCAPS`).
  Выбранное устройство слушается отдельным захватом. Если оно молчит, хотя
  другой микрофон голос слышит (или это виртуальный кабель вроде
  «Voicemeeter Out B1»), вторая дорожка клипа будет тихой: выключите микрофон в
  NVIDIA, голос уже идёт через микс. Если этот же микрофон стоит и во входах
  микса, голос запишется дважды. По последнему клипу NVIDIA в папке записей
  показываются его возраст и звуковые дорожки: NVIDIA подписывает их в файле
  («System sounds», «Microphone»), mp4 читается без ffmpeg
  ([nvidiacheck.go](../nvidiacheck.go));
- устройство записи по умолчанию не подменено виртуальным кабелем, а устройство
  вывода по умолчанию не совпадает с выходом микшера;
- переназначение программ записи.

Дополнительно пишутся образцы `selftest-mix.wav` и `selftest-mic.wav` в
`%LOCALAPPDATA%\maxmix`, их можно просто послушать.

```
maxmixc selftest 10
  [ ok ] Звук в записи                  есть звук, пик -25 dBFS
  [ ok ] Вход: Игра (авто): Game.exe    есть звук, пик -26 dBFS, захватов: 1
  [warn] Вход: Discord.exe              захват работает, но источник молчит
  [warn] Несколько источников           звук только с Игра (авто): Game.exe; молчат: Discord.exe
  [ ok ] Микрофон: Microphone (...)     есть звук, пик -12 dBFS, громкость 100%
  [warn] NVIDIA: микрофон               Voicemeeter Out B1 (...): молчит, вторая дорожка будет тихой; ...
  [info] NVIDIA: дорожки звука          2: System sounds, Microphone
```

## Конфигурация

`maxmix.json` рядом с exe (или `-config путь`). Всё редактируется из окна.

```json
{
  "sources": [
    { "process": "game", "gain": 1.0 },
    { "process": "Discord.exe", "gain": 1.4 },
    { "mic": "Chat-Audeze Maxwell2", "gain": 1.0 }
  ],
  "target": ["CABLE Input", "Voicemeeter AUX Input"],
  "apps": ["steam.exe", "nvcontainer.exe", "NVIDIA Overlay.exe"],
  "sample_rate": 48000,
  "monitor": "Game-Audeze Maxwell2",
  "monitor_gain": 1.0
}
```

У источника ровно одно из `match` / `process` / `mic`. `"process"`: `"game"`,
`"auto"` или имя exe; для `game`/`auto` необязательный `"exclude": [...]`, без
него берётся встроенный список. `"mic"` — часть имени микрофонного устройства.
`target` — кандидаты, берётся первый найденный (если VB-CABLE не установлен, а
Voicemeeter есть, микс пойдёт в `Voicemeeter AUX Input`). `monitor` — устройство,
в котором вы слышите себя во время проверки; на постоянную работу микшера оно не
влияет.

## Ограничения

- **NVIDIA переназначается не сразу.** Windows принимает персональное устройство
  только для процесса, который уже обращался к аудиосервису; `nvcontainer.exe`
  делает это при первой записи или Instant Replay. maxmix повторяет попытку
  каждые 15 с, после первого успеха настройка сохраняется для exe навсегда.
- Звуки клиента Steam (`steam.exe`) после переназначения уходят в виртуальное
  устройство, а не в наушники. Магазин и видео живут в `steamwebhelper.exe`, их
  это не касается. `maxmix unroute` возвращает как было.
- Режим «дерево процессов» единственный в Windows: если родитель и потомок оба
  играют, берётся только родитель, чтобы не было дубликатов.
- Смешивать `match` и `process` можно, но один звук может попасть дважды.
- Микшер должен быть запущен во время записи (`maxmix autostart`).
